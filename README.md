# Цифровая экосистема Центра знаний «Машук»

Платформа сопровождения слушателей образовательных программ АНО «Центр знаний «Машук».
Не LMS: платформа не ведёт курсы, а сопровождает программу — от анонса и расписания
до материалов, общения участников и живой обратной связи.

## Что умеет платформа

На платформе одна программа — международный образовательный семинар
**«Образование на высоте»** (партнёры: Росмолодёжь и «Знание»). Администратор
Центра заводит новые программы в админке.

- **Страница программы** — открыта всем: о программе, расписание по дням,
  материалы, итоги. Без базы показывает демонстрационные данные.
- **Вход по паролю.** Новый участник вводит пароль программы, представляется
  и задаёт личный пароль. Дальше входит по почте или телефону и своему паролю.
  Администратор может завести участника заранее и выдать пароль.
  Защита от перебора: после 8 неверных попыток — блокировка на 15 минут.
- **Рабочее пространство** (`/programs/[slug]/hub`) — только для участников:
  - **канал** — посты команды, комментарии, ответы, реакции, закрепы, фото;
  - **расписание** программы по дням;
  - **сборка программы** — ваша HTML-страница со всеми файлами, закрытая от посторонних;
  - **чаты** — общий чат программы (в нём все), группы и личные диалоги;
    человек получает только свои беседы;
  - **быстрые опросы и квизы** — облако слов, столбцы, шкала, квиз с лидербордом,
    анонимность, выгрузка CSV и PNG; ответы появляются у ведущего в реальном времени;
  - **участники** программы с ролями.
- **Живые обновления** — один поток событий (SSE) на страницу. Браузер
  подтягивает только изменившуюся часть, сообщения о беседе получают только её участники.
- **Админка** (`/admin`) — программы, основное, расписание, материалы, пароль
  программы, участники и роли, загрузка сборки. Администратор Центра видит всё,
  модератор — только свои программы.

## Запуск

Самый простой способ — двойной щёлчок по **`start.cmd`**: скрипт проверит Node.js,
при необходимости установит зависимости, поднимет сервер и откроет браузер.
Подробная инструкция по-русски — в [ЗАПУСК.md](ЗАПУСК.md).

Вручную:

```bash
npm install       # или pnpm install
npm run dev       # http://localhost:4321
npm run build     # production-сборка вместе с проверкой типов
npm run typecheck # только проверка типов
npm run smoke     # дымовая проверка в браузере (нужен запущенный сервер)
npm run shots     # пересобрать скриншоты в docs/screenshots
```

Порт **4321** зафиксирован в скриптах: на машине разработки порты 3000 и 3001
заняты другими проектами. Свой порт — `npm run dev -- -p 4400`.

Требуется Node.js 20+. Без базы открывается только витрина; вход, рабочее
пространство и админка требуют PostgreSQL — см. [ЗАПУСК.md](ЗАПУСК.md).

## Деплой

Прод на VPS (Docker Compose, Caddy с авто-TLS, PostgreSQL, Prometheus/Grafana,
опционально GlitchTip, автоматическая выкладка через GitHub Actions) —
в [ДЕПЛОЙ.md](ДЕПЛОЙ.md).

`pnpm smoke` поднимает headless-браузер, подключается по Chrome DevTools Protocol
и проверяет реальные сценарии: гидратацию редактора, публикацию поста, реакции,
закрепление, переключение ролей, конструктор опросов, ответ участника,
имитацию ответов, чаты и выгрузку файлов. `pnpm shots` делает то же самое
для снимков экрана. Оба скрипта запускаются и через `node scripts/...`.

## Данные и база

Без `DATABASE_URL` открыты только витрина и страница программы — на данных
из `src/lib/mock/`. Вход, рабочее пространство и админка работают с PostgreSQL.

Схема — в [src/lib/db/schema.ts](src/lib/db/schema.ts): программы, дни, события,
материалы, участники, состав программ, посты, комментарии, реакции, опросы,
вопросы, сессии, ответы, беседы, сообщения, отметки о прочтении, сессии входа,
счётчики попыток входа. Запросы — в [src/lib/db/queries.ts](src/lib/db/queries.ts):
данные хаба читаются от имени того, кто смотрит, — свои беседы, свои реакции,
свои ответы.

### Вход

Паролей в открытом виде нет: пароль программы и личные пароли хранятся как
scrypt-хеши. Два пути, оба ведут к личной сессии:

| Путь | Как работает |
| --- | --- |
| Пароль программы | `/programs/<адрес>/enter` → пароль программы → имя, логин, свой пароль |
| Личный пароль | `/join` → почта или телефон и пароль |

Логин — почта или телефон в едином виде (`+7XXXXXXXXXX`). Роль в каждой
программе берётся из `program_members`; администратор Центра (`members.role = admin`)
управляет всеми программами. В браузере лежит только непрозрачный токен сессии
в httpOnly-cookie; в production cookie отдаётся исключительно по HTTPS.
Смена пароля закрывает все прежние входы человека.

### Запись

Публикация постов, комментарии, реакции, закрепы, сообщения в чатах, создание
групп, **ответы на опросы**, **создание опросов и управление живой сессией**
(запуск, переход по вопросам, приём ответов, завершение) выполняются серверными
действиями в [actions.ts](src/app/programs/[slug]/hub/actions.ts). Права
проверяются по сессии и роли в программе, автор берётся из сессии — подписаться
чужим именем или опубликовать пост без прав нельзя. В анонимном опросе участник
не записывается вовсе: анонимность обеспечена тем, что связь с человеком не
хранится.

Интерфейс обновляется сразу, запись уходит в базу следом. Идентификаторы
новых постов, комментариев, сообщений и бесед создаёт браузер (`префикс-UUID`),
поэтому оптимистичная запись и запись в базе совпадают и при обновлении данных
ничего не задваивается. Если база отказала, в хабе появляется предупреждение.

Каждое серверное действие проверяет, что объект принадлежит программе, а данные
корректны ([validate.ts](src/lib/validate.ts)). Ответ на опрос принимается только
на текущий вопрос живой сессии и только один раз: в базе хранится обезличенный
HMAC-ключ участника и сессии, поэтому повтор невозможен и в анонимном опросе.

Идентификаторы вопросов в базе содержат префикс опроса (`poll-…--q1`), потому
что вопросы шаблонов общие для программ. В интерфейс они отдаются **как есть**.

### Живые обновления

Действие публикует событие в шину ([events.ts](src/lib/events.ts)), поток
`/api/events` отдаёт его открытым страницам. События о беседах получают только
их участники. Браузер ([useLiveHub.ts](src/components/hub/useLiveHub.ts))
подтягивает изменившуюся часть через `/api/hub/[part]` с короткой задержкой —
пачка ответов на опрос превращается в один запрос. Состояние живого опроса
приходит прямо в событии.

### Сборка программы

Админка → «Сборка» → папка с `index.html`, стилями, скриптами и файлами
(до 200 МБ). Файлы лежат в `STORAGE_DIR` (по умолчанию `./storage`), не в
`public/`, и отдаются через `/programs/[slug]/build/...` только участникам
программы. Новая загрузка заменяет сборку целиком и атомарно.

### Файлы: фото и сборки

Фото из канала и чатов (`POST /api/upload`) и сборки программ лежат в общем
хранилище ([blob-store.ts](src/lib/blob-store.ts)) с двумя драйверами:

| Драйвер | Когда | Где |
| --- | --- | --- |
| Локальный | по умолчанию | `STORAGE_DIR` (`./storage`, в Docker — том `storage`) |
| S3 | заданы `S3_ENDPOINT` и `S3_BUCKET` | любое S3-совместимое хранилище, path-style |

Клиент S3 ([s3.ts](src/lib/s3.ts)) написан без SDK, подпись — AWS Signature V4,
проверена на эталонных примерах AWS. Бакет приватный: файлы отдаёт приложение
и только вошедшим — фото по `/uploads/ГГГГ-ММ/<uuid>.png`, сборка по
`/programs/<адрес>/build/…`.

Фото — только изображения до 8 МБ. Тип проверяется по содержимому файла,
а не по заявленному браузером: под видом картинки HTML или скрипт не загрузить.
Сборка хранится версиями: новая загружается целиком, затем переключается в базе,
и только потом удаляется старая. Браузер сверяет файлы сборки по ETag и сразу
видит новую версию.

```bash
npm run db:migrate   # применить миграции
npm run db:seed      # очистить базу и заполнить демо-программу (не для рабочего сервера)
npm run db:generate  # сгенерировать миграцию после изменения схемы
npm run admin:create -- admin@mashuk.ru "Имя Фамилия"   # администратор Центра
```

## Источники фирменного стиля

Все значения палитры, типографики и правила использования элементов взяты из
«Руководства по использованию фирменного стиля» АНО «Центр знаний «Машук» (41 стр.):

- основной синий `#223F9A`, тёмный сланец `#332D24`, чёрный `#0A1014`, серый `#DCDEDD`;
- сезонные схемы: весна `#3AD754` / `#0B4D4D`, лето `#FF5B00` / `#F18300`,
  осень `#F24559` / `#F68E9A`, зима `#4582F2` / `#D6E3FB`;
- Geologica — основной шрифт, Noto Serif — для больших текстов, Verdana — только фолбэк;
- **линейные цветовые градиенты не используются**: фон строится на радиальных
  mesh-свечениях, 1px-сетка применяется как паттерн.

## Данные

Программа «Образование на высоте» заполнена реальными данными авторского
одностраничника команды Центра (`lib/mock/programs.ts`). Без базы их показывает
витрина; `npm run db:seed` переносит их в PostgreSQL вместе с демонстрационными
каналом, чатами и опросами.

## Проверка

- `npm run typecheck` и `npm run build` — без ошибок;
- `npm run smoke` — сквозной сценарий в браузере: вход по паролю программы,
  общий чат, изоляция бесед, вход администратора, живой опрос, разделы админки;
- `npm run audit:design` — токены бренда, фокус, контраст.
