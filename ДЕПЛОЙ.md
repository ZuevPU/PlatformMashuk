# Деплой платформы «Центр знаний «Машук»

Прод-стек: приложение (Next.js, standalone) + PostgreSQL + Caddy (TLS) +
Prometheus/Grafana. Опционально — GlitchTip для ошибок.

Всё поднимается через Docker Compose на одном сервере (VPS в РФ, например Timeweb).

```
platform/
  Dockerfile                       образ приложения
  .dockerignore
  docker-compose.yml               app, db, caddy, наблюдаемость, tools
  deploy/
    Caddyfile                      TLS и прокси
    .env.production.example        шаблон переменных
    Dockerfile.tools               миграции и сидинг
    postgres/init/01-glitchtip.sql создаёт базу для GlitchTip
    prometheus/prometheus.yml      сбор метрик
    glitchtip/docker-compose.yml   трекер ошибок (опционально)
    backup.sh / restore.sh         резервные копии
  .github/workflows/deploy.yml     автосборка и выкладка при пуше в main
```

## 1. Сервер

- VPS **Timeweb**, минимум **2 vCPU / 4 ГБ RAM**, Ubuntu 24.04, диск от 40 ГБ.
- На 4 ГБ выставляем **swap 2 ГБ** (иначе Grafana/Prometheus могут не влезть):

  ```bash
  sudo fallocate -l 2G /swapfile && sudo chmod 600 /swapfile
  sudo mkswap /swapfile && sudo swapon /swapfile
  echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
  ```

- Установить Docker и Compose:

  ```bash
  sudo apt update && sudo apt install -y docker.io docker-compose-v2 git
  sudo usermod -aG docker "$USER"   # затем перелогиниться
  ```

- Домен: A-запись (например `mashuk.example.ru`) на IP сервера. Порты 80 и 443 открыты.

## 2. Первый запуск

```bash
sudo mkdir -p /opt/mashuk && sudo chown "$USER" /opt/mashuk
cd /opt/mashuk
# скопируйте сюда содержимое каталога platform (git clone или scp)
cp deploy/.env.production.example .env
nano .env          # DOMAIN, ACME_EMAIL, POSTGRES_PASSWORD, GF_SECURITY_ADMIN_PASSWORD
```

Запуск:

```bash
docker compose --env-file .env up -d
docker compose --env-file .env --profile tools run --rm tools pnpm db:migrate   # создать таблицы
docker compose --env-file .env --profile tools run --rm tools pnpm db:seed      # демо-данные (по желанию)
```

Проверка: `https://DOMAIN` открывает витрину, `https://DOMAIN/api/health` отвечает `"ok": true`.

Вход участников: ссылка `/invite/<токен>`. Токены создаются при сидинге
(например `u-mod-1`, `u-p-01` — см. ЗАПУСК.md).

## 3. Обновления (CI/CD)

Пуш в `main` запускает `.github/workflows/deploy.yml`: собирает два образа,
публикует их в `ghcr.io` и выкладывает на сервер по SSH.

Секреты репозитория (Settings → Secrets and variables → Actions):

| Секрет | Значение |
| --- | --- |
| `SSH_HOST` | IP или домен сервера |
| `SSH_USER` | пользователь (например `deploy`) |
| `SSH_KEY` | приватный SSH-ключ (полный PEM) |
| `SSH_PORT` | порт SSH (необязательно, по умолчанию 22) |
| `DEPLOY_PATH` | каталог проекта на сервере, например `/opt/mashuk` |
| `GHCR_USER` | логин GitHub (если пакет приватный) |
| `GHCR_TOKEN` | PAT с правом `read:packages` (если пакет приватный) |

Создать SSH-ключ для выкладки:

```bash
ssh-keygen -t ed25519 -f deploy_key -C "github-actions"
# публичный ключ → в ~/.ssh/authorized_keys на сервере
# приватный (deploy_key) → в секрет SSH_KEY
```

> Пакеты `ghcr.io` по умолчанию приватные. Либо добавьте `GHCR_TOKEN`/`GHCR_USER`,
> либо переведите оба пакета в публичные (package → Package settings → Change visibility).

Если CI не нужен, обновление вручную:

```bash
cd /opt/mashuk && git pull
docker compose --env-file .env pull
docker compose --env-file .env --profile tools run --rm tools pnpm db:migrate
docker compose --env-file .env up -d
```

## 4. Резервные копии

```bash
deploy/backup.sh                                  # база + загруженные файлы в /var/backups/mashuk
deploy/restore.sh /var/backups/mashuk/db-*.sql.gz # восстановление
```

Автоматически (cron, ежедневно в 03:30):

```cron
30 3 * * * /opt/mashuk/deploy/backup.sh >> /var/log/mashuk-backup.log 2>&1
```

Копии хранятся 7 дней. Для выгрузки во внешнее хранилище настройте `rclone`
и переменную `BACKUP_REMOTE` в `.env`.

## 5. Наблюдаемость

- **Prometheus + node-exporter** — метрики хоста и контейнеров.
- **Grafana** — `https://DOMAIN/grafana/`, логин `admin`, пароль из `GF_SECURITY_ADMIN_PASSWORD`.
  Добавьте источник данных `http://prometheus:9090`.
- **GlitchTip** (ошибки приложения) — отдельно:

  ```bash
  # в .env задайте ERRORS_DOMAIN=errors.example.ru и GLITCHTIP_SECRET_KEY
  # в deploy/Caddyfile раскомментируйте блок {$ERRORS_DOMAIN}
  docker compose -f deploy/glitchtip/docker-compose.yml --env-file .env up -d
  ```

  Затем откройте `https://errors.DOMAIN`, зарегистрируйте первый аккаунт
  (он станет владельцем), создайте проект и получите **DSN**. Пропишите его
  в `.env` как `SENTRY_DSN` и перезапустите приложение:

  ```bash
  docker compose --env-file .env up -d app
  ```

> Отслеживание ошибок заработает после подключения Sentry SDK к приложению
> (пакет `@sentry/nextjs` и `instrumentation.ts`) — это следующий шаг, инфраструктура
> GlitchTip уже готова.

## 6. Важные ограничения

- **Одна реплика.** Шина событий (`src/lib/events.ts`) работает в памяти процесса,
  а живые обновления идут через SSE. Горизонтально масштабировать нельзя без переезда
  на Redis pub/sub.
- **Вход по коду на почту в проде не работает.** `requestLoginCode` отдаёт код
  только вне production, провайдер рассылки не подключён. Действует вход по
  персональной ссылке `/invite/<токен>`. SMTP/SMS подключаются отдельно.
- **Загрузки — в томе `uploads`.** Драйвер S3 в коде ещё не реализован
  (`src/lib/storage.ts` бросает ошибку при заданных `S3_*`).
- **Секреты** хранятся только в `.env` на сервере и в GitHub Secrets, в git не попадают.

## 7. Откат

```bash
cd /opt/mashuk
docker compose --env-file .env down
git checkout <предыдущий-коммит>     # или верните предыдущий тег образа в .env.deploy
docker compose --env-file .env --env-file .env.deploy up -d
```
