# Оптимизация кода

Принцип: **измерить → найти узкое место → минимальная правка → измерить снова**. Не «улучшать» код, который не участвует в проблеме, и не менять поведение.

## 1. Определить область
Если пользователь не назвал файл/экран — спросить, что именно медленно или что оптимизировать. Не проходить весь `src/` целиком.

Карта горячих мест:
| Зона | Файлы |
|---|---|
| Хаб (клиент, крупный) | `src/components/hub/HubApp.tsx`, `Composer.tsx` (TipTap, ленивый через `LazyComposer.tsx`) |
| Опросы | `src/components/polls/PollsView.tsx`, `PollBuilder.tsx`, `src/lib/poll-actions.ts` |
| Чаты | `src/components/chat/ChatView.tsx`, `src/lib/chat-actions.ts` |
| Данные | `src/lib/db/queries.ts`, `src/lib/db/schema.ts`, `src/lib/{data,hub-data}.ts` |
| Экспорт CSV/PNG | `src/lib/export.ts` |
| Реалтайм | `src/app/api/events/route.ts`, `src/lib/events.ts`, `src/components/hub/useLiveHub.ts`, `src/app/api/hub/[part]/route.ts` |
| Вход и админка | `src/lib/auth*.ts`, `src/lib/admin*.ts`, `src/lib/rate-limit.ts`, `src/app/admin/**` |

## 2. Измерить (база)
- `npm run build` + `npm run start`, затем сумма скриптов страницы (Next 16 не печатает размеры): скрипт-замер — в [references/next-react-checklist.md](references/next-react-checklist.md). База на 13.10.2026: витрина ≈563 КБ, хаб ≈689 КБ JS без сжатия; TipTap (393 КБ) — вне первой загрузки.
- `npm run typecheck` — должен быть чистым до и после.
- Для поиска по коду — `Grep` с `head_limit`, а не чтение файлов подряд.

## 3. Чек-лист (подробности и примеры — [references/next-react-checklist.md](references/next-react-checklist.md))
- **Server/Client**: `"use client"` ставится на листья. Статичная разметка, форматирование дат, работа с моками — на сервере. Пропсы в клиентские компоненты — только нужные поля, а не целые объекты программ.
- **Бандл**: TipTap и `export.ts` уже грузятся лениво (`LazyComposer.tsx`, `await import()` по клику) — новые тяжёлые модули подключать так же. `lucide-react` — именованные импорты. `src/lib/mock/*` не должны попадать в клиентские компоненты (проверка: `Grep "mock/" --glob "src/components/**"`).
- **БД (Drizzle)**: нет запросов в цикле (N+1) — заменять на `inArray`/join; выбирать только нужные колонки; индексы на полях фильтрации/сортировки (`programId`, `createdAt`, `channelId`); операции из нескольких записей — в транзакции.
- **Server Actions**: проверка прав и входных данных в начале; общая логика — в хелперах `src/lib/*`, а не копипаста между `hub-actions`, `poll-actions`, `chat-actions`; точечный `revalidatePath`, а не всего сайта.
- **React 19**: убрать `useEffect` для вычислимых значений (считать при рендере); не дублировать состояние; ключи списков — стабильные id; `useMemo`/`useCallback` — только при измеренной пользе; длинные ленты — пагинация/виртуализация.
- **Реалтайм (SSE)**: закрывать подписки при отключении клиента, не слать полное состояние, если хватает дельты.
- **Простота**: мёртвый код, неиспользуемые экспорты, дублирующиеся типы в `src/lib/types.ts`.

## 4. Проверить
- `npm run typecheck`, `npm run build` — сравнить First Load JS с базой и привести разницу в ответе.
- `npm run smoke` (нужны запущенный `npm run dev` и seed) — сквозной сценарий: вход, чаты, опросы, админка.
- Визуально — только если правка затрагивает UI.
