# Безопасность

## Вход и пароли
- Вход по логину (почта или телефон, нормализуется) и **личному паролю**.
- Пароли хранятся как `scrypt`-хеш с солью (`N=16384, r=8, p=1`) — без внешних зависимостей.
- Отдельно есть **пароль программы**: по нему новый участник входит впервые и сам задаёт личный пароль. Через пароль программы нельзя войти в уже существующую запись.
- Защита от перебора: счётчики в БД (`login_attempts`) — 8 попыток/15 мин на логин и 40 на IP, блокировка 15/30 минут. Ответы при ошибке не раскрывают, существует ли логин.

## Сессии
- В браузере — только непрозрачный токен в `httpOnly` cookie `mashuk_session`, `SameSite=Lax`, `Secure` в production, срок 30 дней.
- При новом входе прежняя сессия в этом браузере закрывается; смена пароля завершает все сессии человека.

## Роли и права
- `admin` (администратор Центра) — все программы; `moderator` — свои программы; `participant` — участие и ответы.
- Каждое серверное действие проверяет сессию, роль в программе и принадлежность объекта программе. Автор записи берётся из сессии, а не из запроса.
- Удаление постов/сообщений и модерация Q&A — только команда программы.

## Данные и валидация
- Все входные данные проверяются (`src/lib/validate.ts`): идентификаторы, TipTap-документ (лимит 60 КБ), вложения (до 10), реакции.
- Анонимные опросы: `memberId` не сохраняется; для запрета повторного ответа используется обезличенный `respondentKey` (HMAC от `AUTH_SECRET`).

## Файлы
- Только изображения до 8 МБ, тип проверяется по сигнатуре файла, а не по заявленному MIME.
- Отдача — через `/uploads/...` только вошедшим участникам; авторские сборки программ — только участникам программы.

## Секреты и транспорт
- Секреты — в `.env` на сервере и в GitHub Secrets, в git не попадают.
- HTTPS — Caddy + Let's Encrypt, HSTS, cookie только по HTTPS.
- `AUTH_SECRET` задаётся один раз и не меняется (иначе обезличивание ответов в идущем опросе сломается).

## Известные ограничения
- Один экземпляр приложения (живые события в памяти процесса, SSE).
- Нет двухфакторной аутентификации.
- Восстановление пароля — через администратора (почтовый/SMS-провайдер не подключён).
